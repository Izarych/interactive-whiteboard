# Конфигурация

API читает переменные окружения и локальный `apps/server/.env`. Полный пример находится в
[`apps/server/.env.example`](../apps/server/.env.example). Файлы с секретами не должны попадать в репозиторий.

## Основные параметры

| Переменная | Назначение | Значение для разработки |
| --- | --- | --- |
| `DATABASE_URL` | Подключение к PostgreSQL | `postgresql://user:password@localhost:5432/whiteboard` |
| `AUTH_SECRET` | Секрет для хеширования почтовых кодов | Случайная строка, не менее 32 символов |
| `WEB_ORIGIN` | Адрес веб-клиента | `http://localhost:5173` |
| `PORT` | Порт API | `3000` |
| `HOST` | Адрес прослушивания API | `0.0.0.0` |
| `COOKIE_SECURE` | Cookie только для HTTPS | `false` |

## Почта

| Переменная | Назначение |
| --- | --- |
| `SMTP_HOST`, `SMTP_PORT` | Адрес и порт SMTP-сервера |
| `SMTP_SECURE` | TLS с начала подключения, например для порта 465 |
| `SMTP_REQUIRE_TLS` | Обязательный STARTTLS, например для порта 587 |
| `SMTP_USER`, `SMTP_PASSWORD` | Реквизиты SMTP, если требуется авторизация |
| `MAIL_FROM` | Имя и адрес отправителя |

MailHog использует `localhost:1025`; письма доступны в `http://localhost:8025`.
Коды подтверждения и восстановления действуют 15 минут; повторная отправка доступна через минуту.

## Изображения

По умолчанию используется `STORAGE_PROVIDER=local`, файлы сохраняются в `apps/server/data/uploads`.
Каталог можно изменить через `STORAGE_LOCAL_PATH`. Для S3-совместимого хранилища:

```dotenv
STORAGE_PROVIDER=s3
S3_ENDPOINT=https://storage.yandexcloud.net
S3_REGION=ru-central1
S3_BUCKET=your-bucket
S3_ACCESS_KEY_ID=your-access-key
S3_SECRET_ACCESS_KEY=your-secret-key
```

Файлы доступны через авторизованный API; публичный бакет не требуется.
Смена провайдера применяется к новым загрузкам. Существующие файлы продолжают читаться из своего хранилища.

## Администрирование

Новый административный аккаунт создаётся командой `npm run admin:create`.
Она запрашивает пароль без отображения ввода; для автоматизации доступна переменная `ADMIN_PASSWORD`.
Администратор может изменить роль существующего пользователя, подтвердив действие своим паролем.

Basic Auth для административных маршрутов настраивается в reverse proxy. Пример Nginx находится в
[`deploy/nginx-https.conf`](../deploy/nginx-https.conf); файл паролей хранится вне каталога сайта и репозитория.
Этот слой доступа дополняет авторизацию аккаунта приложения.

## Nginx на сервере

Рабочая конфигурация находится в `/etc/nginx/conf.d/bluviboard.conf` и управляется на сервере. Файлы `deploy/nginx-http.conf` и `deploy/nginx-https.conf` служат шаблонами для первоначальной настройки и восстановления. Обычный автодеплой обновляет приложение и оставляет серверную конфигурацию Nginx под управлением администратора.

Перед правкой сохраните резервную копию вне `conf.d`, например в `/etc/bluviboard/`, затем проверьте и примените изменения:

```sh
nginx -t && systemctl reload nginx
```

Повторный запуск `deploy/tls.sh` сохраняет действующую конфигурацию. HTTPS-шаблон применяется при первоначальном переходе со штатного HTTP-шаблона.

## Проверка Windows-обновлений

Публичный `GET /api/desktop/latest` возвращает `{ "release": ... }` с версией Windows-клиента и ссылкой на его установщик; при отсутствии опубликованного релиза `release` равен `null`. API выбирает стабильные релизы `desktop-v<version>` с готовым x64-установщиком из GitHub Releases. Метаданные кешируются на сервере пять минут, параллельные проверки используют один запрос. Ошибки GitHub или сети возвращают 503.

Установленная версия берётся из Windows-оболочки, независимо от версии веб-интерфейса. Первый клиент 0.1.0 поддерживается через совместимый режим определения версии.

## Браузерные метаданные

`robots.txt` и `sitemap.xml` находятся в `apps/web/public`. Sitemap содержит только публичную главную страницу.
Метаданные приложения и Open Graph заданы в `apps/web/index.html`; изображение превью генерируется при сборке.
