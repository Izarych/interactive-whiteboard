# Самостоятельная Windows-доска (разработка)

## Что меняется

Приложение больше не открывает сайт при запуске. Vite собирает редактор в `apps/desktop/ui`, Tauri встраивает эти файлы в исполняемый файл. Первый запуск, создание досок, рисунки, вставка изображений, настройки, экспорт PNG и файлов `.bluviboard` не требуют сайта, API, аккаунта или предварительного открытия приложения с интернетом. Старый сетевой launcher не используется новой конфигурацией; файлы оставлены для совместимости с тестами прежней оболочки.

Данные хранятся в IndexedDB **локального профиля WebView2 приложения**, не в браузерном профиле сайта. Документы, двоичные изображения и метаданные очереди записываются транзакционно с `durability: strict`. Статус «Сохранено на компьютере» появляется только после завершения транзакции. Отказ диска не считается успешным сохранением; закрытие ждёт записи и завершения текущего штриха. `localStorage` остаётся дополнительным аварийным черновиком, но не основным хранилищем.

Это не шифрование локальных рисунков. Доступ к профилю Windows даёт доступ к данным приложения. Не очищайте данные приложения вручную без резервной копии. Для переноса/резервирования используйте «Действия доски → Сохранить файл доски». Файл содержит документ и изображения, но не пароль или сессию. Импорт создаёт новую доску и новые идентификаторы изображений, не заменяя имеющиеся документы. Удаление программы не должно удалять пользовательский профиль данных.

Установщик использует `webviewInstallMode: offlineInstaller`: WebView2 Runtime включается в дистрибутив. Установщик станет заметно больше, но не должен скачивать среду при установке без интернета. Первая сборка требует сети для получения среды и зависимостей.

## Аккаунт и синхронизация

- Без входа программа работает с отдельным локальным пространством устройства. Оно не отправляется в облако автоматически.
- При входе можно явно отметить перенос локальных досок в аккаунт. Без этой отметки они остаются в локальном пространстве.
- Для каждого аккаунта используется отдельный профиль документов, изображений и настроек. Выход переключает на пространство устройства, не удаляет кэш аккаунта и не показывает его доски другому аккаунту.
- Кэш аккаунта открывается оффлайн при следующем запуске. Истёкшая/отозванная сессия мешает только облачной синхронизации, но не локальному рисованию.
- Пароль не сохраняется. Непрозрачная серверная сессия хранится в Windows Credential Manager и не передаётся JavaScript. При недоступности Credential Manager сессия остаётся в памяти с предупреждением; не используется запасной текстовый файл.
- Сеть доступна только через нативный allowlist-мост к фиксированному `https://bluviboard.ru`. Нельзя указать произвольный URL, читать административные API или передать токен третьему сайту. Перенаправления отключены, TLS проверяется. Разрешения облачного IPC есть только у встроенного локального интерфейса; удалённому сайту оставлено только безопасное закрытие.
- Локальная запись не ждёт сети. Фоновая синхронизация повторяется с задержкой при ошибках. В интерфейсе отдельно показаны локальное сохранение и состояние облака.
- Требуется серверный протокол `GET /api/desktop/sync-capabilities` версии 1. Старый сервер не запускает небезопасный fallback: приложение сообщает о необходимости серверного обновления и продолжает работать локально.

### Конфликты и ограничения первой реализации

Полные оффлайн-документы не объединяются автоматически по принципу «последний победил». Если сайт и программа изменили один документ, обе версии сохраняются: локальная версия получает новое облачное соответствие, исходная облачная доска остаётся нетронутой и скачивается отдельно. Локальная копия помечается в списке досок. Независимые версии могут иметь одинаковые названия — ориентируйтесь на метку и содержимое.

Открытая доска не заменяется в фоне посреди рисования. Полученная облачная версия применяется при повторном открытии либо по кнопке «Открыть изменения с сайта», предварительно сохранив локальные правки.

Совместные доски можно скачать для оффлайн-просмотра. Редактирование такой копии создаёт **отдельную** облачную доску, а не заменяет документ участников. Живое совместное рисование и управление ссылками остаются на сайте: в локальном редакторе кнопка общего доступа скрыта. Это осознанное ограничение, а не обещание синхронного оффлайн-участия в уроке.

Удаления также синхронизируются условно: сервер проверяет ревизию. Если доска изменилась или стала совместной, удаление не применяется, облачная версия сохраняется. Оффлайн-правки удалённой на сайте доски сохраняются новой доской, а не воскрешают прежний идентификатор. Удаления в очереди сохраняются на диск.

## Серверный протокол

`PUT /api/desktop/boards/:id` принимает `UpdateBoard` и UUID `operationId`. Создание с клиентским облачным UUID требует ревизии 0; обновление — точного совпадения ревизии. Подтверждение операции хранится в `desktop_sync_operations` транзакционно с документом и сохраняется даже после удаления доски (удаляется вместе с аккаунтом). Повтор того же `operationId` после потери ответа не создаёт второй документ, не повышает ревизию повторно и не воскрешает удалённую на сайте доску. Даже после включения совместной работы повтор уже подтверждённой операции остаётся безопасным, а новая полная запись отвергается.

`DELETE /api/desktop/boards/:id` принимает ожидаемую `revision`. Существующие проверки владельца, пользователя, изображений, DTO и блокировок сохраняются. Гостям облачная запись недоступна. Для изображений используются прежние авторизованные `/api/assets`, в локальном хранилище ведётся соответствие локальных и облачных UUID.

Перед сетью исходный снимок, UUID операции и тело запроса записываются в локальную очередь. После перезапуска сначала повторяется эта операция. Более свежие локальные штрихи не снимаются с очереди подтверждением старого снимка.

## Проверка и выпуск

```powershell
npm run build
npm run build:offline --workspace @whiteboard/desktop
npx playwright test tests/offline-desktop.spec.ts
npm run desktop:check
npm run desktop:build
```

Нужны Rust из `rust-toolchain.toml` и Visual C++ Build Tools. Windows CI проверяет установленный `.exe` через WebView2: оффлайн-запуск, рисунки/изображения после перезапуска, локальные хоткеи, единственный экземпляр, завершение штриха при закрытии и отказ записи на диск. Браузерные тесты дополнительно проверяют файлы проектов, разделение аккаунтов, конфликт с сайтом, изображения и потерю ответа облака.

Разработка идёт в отдельной ветке без изменения рабочего сайта. Для облака перед выпуском потребуется отдельно согласованная выкладка серверных endpoints. Не повышать публичную версию, не перемещать существующие теги и не публиковать релиз автоматически. Перед публичным выпуском выбрать новую desktop-версию, добавить её заметки и обновить ссылки на установщик согласованно.

В CI не-main ветки собираются с `tauri.preview.conf.json`: отдельное имя **BluviBoard Offline Preview**, идентификатор и запись Credential Manager. Такой установщик не должен заменять обычный клиент или читать его локальный профиль. Его артефакт называется `BluviBoard-Offline-Preview-Setup-<версия>-x64.exe`; опубликованные ссылки на обычный установщик не меняются. Перед будущим переходом с прежней сетевой оболочки дождитесь её синхронизации: неотправленные черновики старого HTTPS-профиля не импортируются автоматически в новый локальный origin, хотя профиль на диске не удаляется.
