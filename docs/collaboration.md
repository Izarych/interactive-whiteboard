# Совместная доска

В редакторе кнопка «Поделиться доской» включает доступ по ссылке `/join#<token>`.
Участник без регистрации может рисовать, стирать, добавлять изображения и выгружать PNG.
Управлять ссылкой может только владелец. Отключение отзывает её и отключает открытые
подключения. Повторное включение создаёт новый случайный 256-битный токен.
Уже полученные изображения и рисунки невозможно удалить с чужого устройства.

## Синхронизация

- WebSocket `/api/collaboration/socket`; секрет передаётся в первом сообщении, не в HTTP URL.
- Владелец использует обычную проверку сессионной cookie, участник — токен одной доски.
- Проверка Origin при upgrade, авторизация каждого изменения, ограничение размера,
  частоты и очереди сообщений; heartbeat и повторная проверка доступа.
- Сервер применяет условные поэлементные операции под блокировкой строки PostgreSQL.
  Идентификаторы операций сохраняются в БД: повтор после потери ответа не дублирует изменения.
- Добавления разных объектов объединяются. При конкурентной правке одного объекта
  сохраняется первая принятая версия: устаревшая операция не заменяет более новую.
  Отмена меняет только объекты локального действия, не снимок всей доски.
- Превью штрихов временные, не сохраняются. Завершённое превью остаётся видимым
  до получения сохранённого объекта, в том числе при начале следующего штриха.
  Отменённый жест удаляется отдельно, без удаления ожидающих подтверждения линий.
- Клиенты с протоколом 2 получают подтверждённые поэлементные изменения, а не
  полную доску на каждый штрих. Полный документ загружается при входе, переподключении
  и восстановлении пропущенных ревизий. Старые клиенты продолжают получать снимки.
  Переставленные сетью изменения применяются по ревизиям; локальный штрих не
  убирается из очереди раньше, чем его подтверждение можно применить.
- Проверки доступа к превью и исходящим сообщениям не загружают документ из БД.
  Сама авторизация остаётся на каждом сообщении. При переподключении очередь
  локальных операций отправляется повторно.
- Очередь хранится в локальном черновике. У участника черновик привязан к конкретной
  ссылке и не переносится на новое поколение доступа.
- После первого включения доска остаётся на поэлементном протоколе и для владельца,
  даже когда ссылка отключена. Старые полные PUT-снимки отклоняются с конфликтом.
  Остальные доски сохраняют прежний протокол с проверкой ревизии.
- Изображения участника загружаются с токеном в заголовке через отдельный endpoint;
  доступны только изображения этой доски, без доступа к профилю и другим файлам.

## Развёртывание

Пока реализация рассчитана на **один процесс API**: комнаты WebSocket живут в памяти,
документы и подтверждения операций — в PostgreSQL. Для нескольких API-процессов нужна
межпроцессная рассылка событий (включая отзыв доступа), например через Redis.

В шаблон `deploy/nginx-https.conf` добавлен отдельный location с WebSocket Upgrade.
Обычный деплой **не должен заменять рабочий Nginx-конфиг**. Перед публикацией этот
location нужно отдельно добавить в действующий конфиг, проверить `nginx -t` и
перезагрузить Nginx. Локальный Vite проксирует WebSocket автоматически.
