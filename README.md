# BluviBoard

Браузерная доска для рисунков, заметок и скриншотов. Создавайте отдельные доски для задач, работайте в гостевом режиме или сохраняйте их в аккаунте.

[Открыть приложение](https://bluviboard.ru) · [Релизы](https://github.com/Izarych/interactive-whiteboard/releases) · [Сообщить об ошибке](https://github.com/Izarych/interactive-whiteboard/issues)

## Возможности

- Карандаш, палитра, фигуры, ластик, отмена и повтор действий.
- Настраиваемые хоткеи инструментов: клавиша или сочетание, повторное нажатие возвращает предыдущий инструмент.
- Выравнивание линии, квадрата, прямоугольника, треугольника, круга и эллипса по настраиваемому модификатору.
- Точечный ластик с сохранением оставшихся частей рисунка; Shift удаляет весь исходный объект.
- Масштабирование, перемещение и разметка холста: точки или клетка с настройкой размера.
- Вставка скриншотов через Ctrl+V, загрузка изображений и экспорт PNG.
- Несколько досок, автосохранение и восстановление локального черновика.
- Гостевой режим с переносом досок в аккаунт, подтверждение почты, профиль и восстановление пароля.
- Административная панель для управления пользователями, гостями и досками.
- Установка как PWA с отдельным окном и ярлыком приложения.
- Отдельный Windows-клиент на Tauri 2 с установщиком `.exe`.

## Установка приложения

### Windows-клиент

Скачайте установщик из [релизов Windows-клиента](https://github.com/Izarych/interactive-whiteboard/releases?q=desktop-v&expanded=true) и запустите его. Приложение поддерживает Windows 10/11 x64, устанавливается для текущего пользователя и использует WebView2. Установщик добавляет ярлыки и запись для удаления приложения; при необходимости загружает WebView2.

Вход сохраняется между запусками, отдельно от браузера. При закрытии окна приложение завершает штрих и ждёт загрузки изображений и сохранения доски. При ошибке можно повторить сохранение, продолжить работу или явно закрыть окно с риском потери несохранённых изменений.

Проверка новых Windows-версий запускается автоматически при открытии клиента. Кнопка **«Проверить обновления»** доступна на экране входа и в боковой панели. Если опубликован новый установщик, приложение показывает установленную и доступную версии и предлагает **«Скачать обновление»**. Перед скачиванием оно завершает активное рисование и сохраняет доску. Закройте приложение и запустите скачанный установщик. Ошибка проверки отображается отдельно; она не означает, что установлена актуальная версия.

Установщик пока без подписи издателя: Windows может показывать предупреждение о неизвестном приложении. Для работы нужен интернет. Интерфейс обновляется с сайта; новую версию оболочки устанавливают запуском следующего установщика.

### PWA

Откройте сайт в Chrome или Edge и нажмите **«Установить BluviBoard»**. Установку можно также запустить из меню браузера или адресной строки. На Windows приложение появляется в меню «Пуск» и открывается в отдельном окне; вход использует тот же профиль браузера.

При появлении новой версии приложение предлагает обновление. По кнопке **«Обновить»** оно завершает текущий рисунок, дожидается загрузки изображений и сохранения доски, затем перезапускается. При ошибке сохранения обновление откладывается; кнопка **«Позже»** позволяет продолжить работу.

Для открытия досок нужен интернет. При запуске без сети отображается страница восстановления подключения. Service worker хранит только эту публичную страницу, а данные досок, изображения и ответы API получает с сервера.

## Рисование и ластик

Нажмите **Shift** во время рисования карандашом: распознанная линия, прямоугольник, квадрат, треугольник, круг или эллипс выравниваются. Превью и выравнивание сохраняются до завершения текущего штриха, даже если отпустить Shift раньше кнопки мыши или пера. Следующий штрих без модификатора рисуется свободно; нераспознанный рисунок сохраняет исходную форму. Для инструментов «Прямоугольник» и «Эллипс» модификатор задаёт квадрат и круг.

Хоткей можно выбрать в **«Цвет и толщина» → «Выравнивание фигур»**: Shift, Alt или Ctrl. Предпочтение сохраняется между запусками.

Чтобы назначить хоткей инструменту, нажмите на него правой кнопкой или выберите инструмент и нажмите значок клавиатуры в панели. В поле настройки нажмите нужную клавишу (например, CapsLock) или сочетание (например, Ctrl+F1), затем **«Сохранить хоткей»**. Повторное нажатие возвращает предыдущий инструмент. По умолчанию хоткеи инструментов не назначены; ваши настройки сохраняются на сервере для всех досок и доступны после повторного входа. В полях ввода инструменты по хоткеям не переключаются. Удалить назначение можно кнопкой **«Убрать хоткей»**.

Обычный ластик стирает участок линии или контура. Размер кисти настраивается в том же меню. **Shift + ластик** удаляет весь исходный объект, включая его ранее разрезанные части; изображения удаляются целиком этим режимом или через выделение и Delete. Стирание поддерживает отмену/повтор и сохранение на сервере.

## Локальная разработка

### Требования

- Node.js 24 LTS и npm 11.
- PostgreSQL 16 или совместимая версия.
- SMTP-сервер. Для разработки можно использовать MailHog на портах 1025 и 8025.

### Установка

```sh
git clone https://github.com/Izarych/interactive-whiteboard.git
cd interactive-whiteboard
npm ci
```

Скопируйте [`apps/server/.env.example`](apps/server/.env.example) в `apps/server/.env`.
Укажите `DATABASE_URL` и случайный `AUTH_SECRET` длиной не менее 32 символов:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Создайте базу данных и запустите приложения:

```sh
npm run db:setup
npm run dev
```

Клиент доступен на `http://localhost:5173`, API — на `http://localhost:3000/api`.
Vite проксирует запросы `/api` на сервер. Если база уже создана, шаг `db:setup` можно пропустить.
Таблицы и индексы создаются при запуске API.

Service worker включён только в production-сборке; `npm run dev` не регистрирует его. Иконки генерируются из `favicon.svg` при запуске и сборке. PWA-сценарии проверяются через Playwright на собранном клиенте.

### Разработка Windows-клиента

Для сборки нужны Windows x64, Rust 1.98.1, Visual Studio Build Tools с компонентом **Desktop development with C++**, Windows SDK и WebView2. После `npm ci`:

```sh
npm run desktop:dev
npm run desktop:build
```

Клиент открывает `https://bluviboard.ru`. Локальная стартовая страница встроена в исполняемый файл, профиль WebView2 хранится в каталоге приложения `ru.bluviboard.desktop` в `%LOCALAPPDATA%`. Внешние HTTP(S)-ссылки открываются в браузере.

Для автоматизации WebView2 используйте `BLUVIBOARD_DESKTOP_DEBUG_PORT` — номер локального CDP-порта — и `BLUVIBOARD_DESKTOP_TEST_DATA_DIR` — абсолютный путь к отдельному тестовому профилю. Параметры передаются напрямую через API WebView2, что поддерживает проверки на Windows-runner с WebView2 150+.

Установщик находится в `apps/desktop/src-tauri/target/release/bundle/nsis/`. `node apps/desktop/scripts/package.cjs` создаёт файл со стабильным именем и SHA-256 в `apps/desktop/artifacts/`.

Workflow **Windows installer** собирает и проверяет настоящий Windows-клиент, сохраняет установщик как артефакт и при первом успешном запуске новой desktop-версии в `main` публикует релиз `desktop-v<version>`. Desktop-релизы имеют отдельную нумерацию и не заменяют основной релиз сайта. Для следующей версии обновите `apps/desktop/package.json`, `src-tauri/Cargo.toml`, Cargo.lock и добавьте `docs/releases/desktop/<version>.md`. Уже опубликованные установщики не перезаписываются.

## Структура проекта

```text
apps/
  desktop/   Tauri 2, стартовая страница и Windows-установщик
  web/       React, TypeScript, Vite и Konva
  server/    NestJS API, авторизация, почта и хранилище
packages/
  shared/    Общие типы документов и API
tests/       Интеграционные и браузерные проверки
docs/        Конфигурация и история изменений
deploy/      Скрипты развёртывания
```

Доска хранится как объектный документ: штрихи, фигуры и изображения имеют собственные идентификаторы.
Документы сохраняются в PostgreSQL; файлы — в локальном каталоге или S3-совместимом хранилище.
Ревизии документов защищают от перезаписи изменений из другой вкладки. Доступ к данным проверяется по владельцу пространства.

Параметры SMTP, хранилища и авторизации описаны в [конфигурации](docs/configuration.md).

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск клиента и API |
| `npm run dev:web` | Только клиент |
| `npm run dev:server` | Только API |
| `npm run build` | Сборка веб-клиента и API |
| `npm run desktop:dev` | Запуск Windows-клиента |
| `npm run desktop:build` | Сборка Windows-установщика |
| `npm run desktop:check` | Проверка форматирования и Rust-тесты |
| `npm run test:api` | Интеграционные проверки API |
| `npm run test:e2e` | Браузерные проверки Playwright |
| `npm run test:drawing` | Геометрия распознавания фигур и точечного стирания |
| `npm run test:updates` | Выбор Windows-релиза, кеширование и ошибки проверки |
| `npm run admin:create -- --email admin@example.com --name "Administrator"` | Создание административного аккаунта |
| `npm run mail:preview -- --to you@example.com` | Отправка тестового письма |

## Проверки

Для интеграционных проверок нужны PostgreSQL и MailHog. Перед первым запуском браузерных тестов установите Chromium:

```sh
npm run build
npx playwright install chromium
npm run test:api
npm run test:e2e
```

Проверки аккаунтов и браузерные тесты используют временные схемы PostgreSQL. Созданные тестами данные, файлы и письма удаляются после выполнения.
