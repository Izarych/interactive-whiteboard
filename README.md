# BluviBoard

Текущая версия: **1.0.0**. Описание официального релиза: [`docs/releases/1.0.0.md`](docs/releases/1.0.0.md).
Production: **https://bluviboard.ru**. Автодеплой проверенных коммитов `main` не создаёт теги
и GitHub Releases; официальные релизы публикуются по отдельным версиям `X.Y.Z`.

Интерактивная доска: React/TypeScript + Konva, NestJS и PostgreSQL в npm-монорепозитории.

Название продукта — **BluviBoard** («БлувиБорд»). Логотип и SVG favicon находятся в
`apps/web/public/favicon.svg`. Кандидат для домена — **bluviboard.ru**: 30 сентября 2026 года
WHOIS реестра `whois.tcinet.ru` ответил `No entries found`. Домен не зарегистрирован на момент
проверки; актуальную доступность нужно проверить перед покупкой.

## Возможности

- Вход, регистрация с подтверждением почты шестизначным кодом и гостевой режим.
- Автоматический перенос гостевых досок и изображений в новый аккаунт; объединение при входе в существующий.
- Редактирование имени и аватара, восстановление пароля по почтовому коду.
- Админ-панель: аналитика, пользователи, гости, доски, изображения, почта и журнал действий.
- Несколько досок: создание, переключение, переименование и удаление с подтверждением.
- Карандаш, палитра и произвольный цвет, толщина линии.
- Фон «Чистый», «Точки» или «Клетка», ползунок и точное значение размера разметки с сохранением отдельно для каждой доски.
- Прямоугольники, эллипсы и ластик, удаляющий штрих или фигуру целиком.
- Вставка скриншотов через Ctrl+V, загрузка PNG/JPEG/WebP и перетаскивание файлов на холст.
- Перемещение, изменение размера и удаление изображений; изображения включаются в экспорт PNG.
- Отмена/повтор последних 50 действий, очистка холста с возможностью отмены.
- Масштабирование колёсиком и кнопками; перемещение инструментом «Рука» или средней кнопкой мыши.
- Экспорт видимой области в PNG с белым фоном.
- Автосохранение в PostgreSQL через 800 мс после изменений и перед переключением досок.
- Индикатор сохранения, повторная попытка вручную или при восстановлении соединения браузера.
- Локальный черновик для восстановления несохранённых изменений после перезагрузки.
- Хранение изображений на локальном диске по умолчанию или в Yandex Object Storage (S3).

## Структура

- `apps/web` — веб-клиент React + TypeScript (Vite).
- `apps/server` — NestJS API; доступ к PostgreSQL через `pg`.
- `packages/shared` — общие TypeScript-типы досок и графических объектов.
- `tests` — интеграционные проверки API и браузерные проверки Playwright.

## Требования

- Node.js 20.19+ или 22.12+ (проект проверен на Node.js 24).
- npm 10+.
- Запущенная PostgreSQL.
- Для локальных писем — MailHog: SMTP `localhost:1025`, веб-интерфейс `http://localhost:8025`.

## Запуск

```sh
npm install
```

Создайте `apps/server/.env` по примеру `apps/server/.env.example` и задайте подключение:

```dotenv
DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@localhost:5432/interactive_whiteboard
PORT=3000
WEB_ORIGIN=http://localhost:5173
AUTH_SECRET=your-random-secret-of-at-least-32-characters
COOKIE_SECURE=false
SMTP_HOST=localhost
SMTP_PORT=1025
SMTP_SECURE=false
MAIL_FROM=BluviBoard <no-reply@bluviboard.local>
```

Специальные символы в логине/пароле нужно кодировать для URL. Локальный `.env` игнорируется Git.
Для `AUTH_SECRET` сгенерируйте случайное значение, например:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

```sh
npm run db:setup
npm run dev
```

`db:setup` создаёт указанную базу, если её ещё нет; пользователю PostgreSQL для этого нужно право
`CREATEDB`. Для уже созданной базы этот шаг можно пропустить. При запуске API выполняется
идемпотентная миграция таблиц досок, изображений, пользователей, владельцев пространств,
сессий и почтовых запросов. Существующие рисунки и файлы сохраняются.

- Клиент: **http://localhost:5173**
- API: **http://localhost:3000/api**
- Проверка запуска: **http://localhost:3000/api/health**

Vite проксирует `/api` на API. При изменении порта сервера задайте `API_PROXY_TARGET`
в окружении Vite (по умолчанию `http://localhost:3000`).

## Сохранение и данные

Каждая доска хранит название и объектный документ `JSONB` вида `{ version: 1, elements: [...] }`.
Штрихи и фигуры содержат UUID, тип (`stroke`, `rectangle`, `ellipse`), цвет, толщину и координаты
в пространстве холста. Изображение (`image`) содержит `assetId`, положение `x`/`y` и размеры
`width`/`height`; байты изображения хранятся отдельно от документа. Масштаб/положение камеры и история отмены относятся к текущему сеансу
редактирования. Рисунок сохраняется между запусками.

Запросы сохранения выполняются последовательно. Если рисунок меняется во время запроса,
следом отправляется актуальная версия. Номер ревизии защищает от затирания изменений
из другой вкладки: при конфликте можно сохранить локальный рисунок отдельной доской.

При сбое API появляется сообщение и кнопка повторного сохранения. Перед закрытием вкладки
с несохранёнными изменениями браузер показывает предупреждение; локальный черновик
восстанавливается при следующем открытии этой доски, если доступен `localStorage`.

API ограничивает документ 10 МБ, 10 000 объектами и 20 000 парами координат в одном штрихе.

## Аккаунты, гости и почта

На стартовой странице доступны **«Вход»**, **«Регистрация»** и **«Продолжить как гость»**.
Гость получает собственное пространство с досками и сессию в HttpOnly cookie. Доски гостя
восстанавливаются при повторном открытии в том же браузере, пока сохраняется cookie сессии.

Для регистрации укажите почту, пароль (не менее 8 символов) и имя; аватар необязателен.
Затем введите шестизначный код из письма. Аккаунт создаётся только после подтверждения почты.
Гостевое пространство становится пространством пользователя без копирования или потери
досок, штрихов, настроек фона и изображений. При входе гостя в уже существующий аккаунт
его доски и изображения также объединяются с данными аккаунта.

В боковой панели можно открыть **профиль**, изменить имя, заменить/удалить аватар и выйти.
Аватары используют выбранное локальное/S3-хранилище и нормализуются в PNG 512×512.
Изображения досок и аватары выдаются владельцу или администратору через авторизованный API.

Кнопка **«Забыли пароль?»** находится на форме входа. Введите почту, код из письма и новый
пароль. Восстановление также доступно из профиля через **«Сбросить пароль»**. После смены
пароля все пользовательские сессии завершаются; доски остаются в аккаунте.

Почтовые коды действуют **15 минут**; повторная отправка доступна через **60 секунд**.
После пяти неверных попыток код нужно запросить заново. Пароли хранятся как salted scrypt
хеши; в базе сессий сохраняются хеши случайных токенов, а кодов — HMAC-хеши с `AUTH_SECRET`.
Срок пользовательской сессии — 30 дней, гостевой — 180 дней.

### Локальная почта в MailHog

При настройках из `.env.example` письма отправляются по SMTP на **localhost:1025** и
появляются в **http://localhost:8025**. MailHog перехватывает локальные письма — их коды
нужно брать в этом веб-интерфейсе, а не во внешнем почтовом ящике.

Письма регистрации и восстановления имеют фирменный HTML-шаблон: синюю шапку BluviBoard,
крупный код, срок действия, кнопку перехода и футер. Для клиентов без HTML также отправляется
текстовая версия. Шаблон находится в `apps/server/src/auth/mail.template.ts`.

После сборки сервера можно отправить письмо-пример без создания аккаунта или изменения пароля:

```sh
npm run build:server
npm run mail:preview -- --to you@example.com
```

Для другого SMTP-сервера задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `MAIL_FROM` и,
если требуется авторизация, `SMTP_USER` / `SMTP_PASSWORD`. Для работы приложения через HTTPS
задайте `COOKIE_SECURE=true` и точный адрес сайта в `WEB_ORIGIN`. Запросы с изменением данных
проверяют Origin; API использует cookie и CORS с credentials.

### Доски, созданные до появления аккаунтов

У прежних досок и изображений изначально нет владельца. Чтобы назначить их своему аккаунту,
укажите в локальном `.env` **`LEGACY_OWNER_EMAIL=you@example.com`**, затем зарегистрируйте и
подтвердите эту почту (или войдите в уже подтверждённый аккаунт с таким адресом).
Доски и изображения без владельца будут назначены этому пользователю. До этого они остаются
в базе и недоступны другим гостям и аккаунтам. Настройку владельца задаёт администратор сервера.

### Клетчатый холст

В строке **«Фон доски»** выберите **«Клетка»** или **«Точки»**: рядом появятся ползунок и поле
для точного размера. Можно выбрать любое целое значение **от 12 до 96**; например, 24 для
обычной разметки или 48 для крупной. Изменение сразу видно на холсте. Введённое значение за
пределами диапазона корректируется при выходе из поля или нажатии Enter. Разметка помогает записывать цифры и вести
вычисления; она масштабируется и перемещается вместе с рисунком. Переключение фона не меняет
содержимое доски и не привязывает штрихи к узлам сетки.

Настройка хранится в документе как `background: { pattern: 'grid', size: 32 }` и сохраняется
автоматически, включая черновики и копии досок. Документы старой версии без `background`
открываются с точками с шагом 24. Отмена/повтор рисунка и очистка холста сохраняют выбранный фон.
При экспорте PNG разметка остаётся вспомогательной: изображение экспортируется на белом фоне.

## Изображения и скриншоты

Сделайте скриншот в буфер обмена (например, Win+Shift+S), вернитесь на доску и нажмите **Ctrl+V**.
Для файлов используйте кнопку **«Изображение»** или перетащите файл на холст. При вставке из
буфера изображение появляется по центру видимой области, при перетаскивании — в точке сброса.
Вставка в поле названия доски сохраняет обычное поведение текстового поля.

После добавления активируется **«Выделение»**: перетаскивайте изображение для перемещения,
тяните за углы для изменения размера с сохранением пропорций, нажмите **Delete** или кнопку
**«Удалить изображение»** для удаления. Ластик также удаляет изображение целиком.
Эти действия поддерживают отмену/повтор и автосохранение. Перед переключением доски клиент
дожидается завершения текущих загрузок и сохранения документа.

Поддерживаются статичные PNG, JPEG и WebP до **10 МБ**, **25 мегапикселей** и **10 000 пикселей**
по каждой стороне. Сервер проверяет содержимое, учитывает ориентацию и сохраняет изображения
в PNG без метаданных; полученный PNG также должен укладываться в 10 МБ.

### Локальное хранилище — по умолчанию

Дополнительная настройка не нужна. В `apps/server/.env` при необходимости можно указать:

```dotenv
STORAGE_PROVIDER=local
STORAGE_LOCAL_PATH=./data/uploads
```

По умолчанию файлы размещаются в **`apps/server/data/uploads`**. Относительный путь считается
от рабочей директории сервера (`apps/server` при запуске через npm workspace). Каталог создаётся
автоматически и исключён из Git. Для переноса или резервного копирования нужны **база и этот каталог**.

### Yandex Object Storage

Создайте бакет и статический ключ сервисного аккаунта с правами чтения и записи объектов
(например, ролью `storage.editor` для нужного бакета), затем настройте `apps/server/.env`:

```dotenv
STORAGE_PROVIDER=s3
S3_ENDPOINT=https://storage.yandexcloud.net
S3_REGION=ru-central1
S3_BUCKET=your-bucket
S3_ACCESS_KEY_ID=your-static-access-key
S3_SECRET_ACCESS_KEY=your-secret-key
```

Перезапустите API. Новые файлы будут отправляться в бакет. Бакет может оставаться приватным:
изображения выдаются через `GET /api/assets/:id`, поэтому клиенту не нужны облачные ключи,
публичные ссылки или отдельные настройки CORS бакета.

Для каждого файла в базе сохраняются выбранный провайдер, бакет и ключ. Переключение провайдера
не переносит уже загруженные файлы: старые локальные изображения продолжают читаться с локального
диска, облачные — из сохранённого бакета при наличии подходящих ключей. При изменении локального
каталога ранее загруженные файлы нужно перенести в новый путь.

Файлы изображений живут независимо от досок: очистка холста или удаление объекта не удаляет
сам файл, чтобы сохранить отмену действия, черновики и копии досок с теми же изображениями.

## Админ-панель

### Создание администратора — только серверной командой

Из корня репозитория выполните:

```sh
npm run admin:create -- --email admin@example.com --name "Administrator"
```

Команда собирает сервер, запрашивает пароль без отображения ввода, создаёт **новый**
подтверждённый аккаунт с ролью `admin` и записывает действие в журнал. Для автоматизации пароль
можно передать через переменную окружения `ADMIN_PASSWORD`. Если почта уже занята, команда
откажется создавать аккаунт: существующие пользователи через неё не повышаются в правах.

Новый административный аккаунт создаётся серверной командой. Существующему пользователю
администратор может изменить роль в профиле пользователя, подтвердив действие своим паролем.
После изменения роли сессии целевого пользователя отзываются и требуется повторный вход.
Обычная регистрация не принимает роль; самостоятельное снятие административной роли запрещено.
Все маршруты `/api/admin/*` проверяют роль в базе на каждом запросе; гостям и обычным аккаунтам
они недоступны. Через панель можно создавать только обычных пользователей.

Войдите с созданной почтой и паролем и откройте **http://localhost:5173/admin** или кнопку
**«Админ-панель»** в боковой панели досок.
Страница `/admin` содержит только административный вход и восстановление пароля, без
регистрации и гостевого входа. Вход проверяет административную роль также на сервере.

### Разделы и возможности

- **Обзор:** пользователи, гостевые пространства, доски, объём хранилища, действующие сессии,
  активность за неделю, ожидающие подтверждения регистрации, графики за 7/30/90 дней и последние записи.
- **Пользователи:** поиск, пагинация, статус и роль, количество досок/сессий; создание обычного
  аккаунта, имя, аватар, новый пароль, блокировка/разблокировка, отзыв сессий и удаление вместе с данными.
- **Гости:** доски, файлы и последнее посещение; блокировка пространства, удаление и передача
  **всех** гостевых досок/изображений подтверждённому аккаунту по его почте. Блокировка гостевого
  пространства ограничивает это пространство, а не все будущие гостевые сессии посетителя.
- **Доски:** поиск по названию, UUID и почте владельца, информация об объектах/изображениях,
  интерактивный просмотр с масштабом и перемещением, переименование, очистка рисунка и удаление.
- **Изображения:** миниатюры, владелец, размеры, объём, тип и хранилище; просмотр и удаление
  неиспользуемых файлов. Файл, который связан с доской или аватаром, сначала нужно убрать из содержимого.
- **Журнал действий:** административные операции с датой, исполнителем и подробностями;
  пароли и их хеши в журнал не записываются.
- **Почта:** отправка фирменного тестового письма на выбранный адрес.

Аналитика строится по реальным данным PostgreSQL; графики используют Recharts, интерфейс —
иконки Lucide и оформление BluviBoard. События активности начинают собираться после установки
этой версии. История создания сохраняется для аналитики даже после удаления соответствующей записи.
Самостоятельная блокировка или удаление текущего административного аккаунта запрещены.

## API досок

Все операции с досками и изображениями требуют пользовательскую или гостевую сессию.
Список возвращает только свои доски; для обычных пользователей чужие UUID досок/изображений возвращают 404.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/boards` | Список досок без графического документа |
| POST | `/api/boards` | Создать доску: `{ title }` |
| GET | `/api/boards/:id` | Загрузить доску с документом |
| PUT | `/api/boards/:id` | Сохранить: `{ title, document, revision }` |
| DELETE | `/api/boards/:id` | Удалить доску (204) |
| POST | `/api/assets` | Загрузить изображение: multipart-поле `file`; ответ `{ id, url, width, height }` |
| GET | `/api/assets/:id` | Получить PNG из локального или S3-хранилища |
| POST | `/api/assets/avatar` | Загрузить аватар: multipart-поле `file` |

## API аккаунтов

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/auth/session` | Текущая сессия: anonymous, guest или user |
| POST | `/api/auth/guest` | Создать/продолжить гостевую сессию |
| POST | `/api/auth/register` | Запросить код регистрации: `{ email, password, name, avatarAssetId? }` |
| POST | `/api/auth/register/resend` | Повторить письмо: `{ challengeId }` |
| POST | `/api/auth/verify-email` | Подтвердить почту: `{ challengeId, code }` |
| POST | `/api/auth/login` | Войти: `{ email, password }` |
| POST | `/api/auth/logout` | Выйти из текущей сессии |
| PATCH | `/api/auth/profile` | Изменить `{ name, avatarAssetId? }`; null удаляет аватар |
| POST | `/api/auth/forgot-password` | Запросить код восстановления: `{ email }` |
| POST | `/api/auth/reset-password` | Установить пароль: `{ challengeId, code, password }` |

Административный API: `/api/admin/overview`, `/users`, `/guests`, `/boards`, `/images`, `/audit`,
`/mail/preview`. Он поддерживает поиск и пагинацию списков, управление профилями/паролями,
блокировку, отзыв сессий, передачу гостевого пространства, очистку и удаление данных.

## Проверки

Настройте `.env` и базу по инструкции выше, затем:

```sh
npm run build
npm run test:api
npx playwright install chromium
npm run test:e2e
```

API-тесты запускают собранный сервер на порту `3101` и проверяют CRUD, валидацию,
конфликты, загрузку изображений и сохранность данных/файлов после перезапуска. S3-адаптер
проверяется с локальным HTTP-стендом: подпись запросов, запись, чтение и удаление объекта.
Проверки аккаунтов используют сервер на `3103` и отдельную временную схему PostgreSQL:
изоляция владельцев, подтверждение почты, перенос гостевых данных, профиль, лимиты кодов,
восстановление пароля, отзыв сессий и назначение старых досок. Проверяются серверная команда
администратора, защита роли, административные операции, аналитика, журнал и HTML-письма.
Браузерные тесты запускают API на `3102`
и Vite на `5174`: рисование, ластик, отмена/повтор, переключение досок, автосохранение,
восстановление черновика, очередь сохранений, экспорт и удаление, вставку из реального буфера,
загрузку/перетаскивание файлов, перемещение и изменение размера изображений, клетчатый фон,
сохранение разметки между досками и перезагрузками, гостевой вход, регистрацию, подтверждение
почты, изменение профиля, восстановление пароля и административный интерфейс. Браузерные проверки работают в отдельной
временной схеме PostgreSQL и отдельном каталоге `.test-data`. Тестовые схемы, файлы и письма
MailHog удаляются после проверок; пользовательские доски и письма не затрагиваются.
